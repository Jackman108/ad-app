# Стратегический план — Завхоз (бывш. Ad App / Объявки BY)

**Обновлено:** 04.11.2026  
**Статус:** пивот принят — [ADR 0004](../adr/0004-product-pivot-zavhoz.md)  
**Бизнес-модель:** [business-model-zavhoz-ru.md](business-model-zavhoz-ru.md)

## Цель продукта

B2B-платформа **«Завхоз на аутсорсе»** в РБ: коммерческие точки создают заявки на мелкий ремонт/эксплуатацию; платформа диспетчеризирует мастеров; закрытие — фото-отчёт и акт. Безнал и легальный контур — ценность №1 для клиента.

## Архив: Объявки BY

C2C-доска (S0–S7) **заморожена**. Код остаётся в репо как reference; новые спринты объявлений не планируем без отдельного ADR.

## Принципы исполнения

1. **Сначала инварианты домена** (ADR 0005), потом массовый rewrite схемы  
2. **YAGNI** — платежи/ЭДО/подписки сетей не в первой миграции Завхоз  
3. **Clean Architecture** — use-case → порты → Prisma; без сырого Prisma в JSX  
4. **Чистые фото** — `WorkOrderImage` (до/после), оригинал байтов без лишнего перекодирования  
5. Документация и rules обновляются вместе с решениями

### Фаза Z1 — Вертикаль заявки

- Создать заявку (бизнес) + фото «до»  
- Список/карточка заявки (диспетчер)  
- Назначить / принять мастером  
- Фото «после» + закрытие статуса  

**Критерий:** один счастливый путь без оплаты.

### Фаза Z2 — Диспечер и гео

- Радиус / locality мастера  
- Уведомления (in-app → позже push/SMS)  
- Базовый прайс по категориям работ  

### Фаза Z3 — Деньги и юр. контур

- Баланс/счёт, комиссия платформы  
- Акт / выгрузка для ЭДО (минимум)  
- Подписка на объект (retainer) — после сигнала спроса  

### Фаза Z4 — Качество и рост

- Playwright по Z1  
- Rate limits, аудит мастеров  
- Расширение услуг (клининг и т.д.) только после PMF
