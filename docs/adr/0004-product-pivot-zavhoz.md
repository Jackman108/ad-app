# ADR 0004 — Пивот продукта: B2B «Завхоз на аутсорсе»

- **Статус:** Принято (04.11.2026, решение владельца продукта)
- **Дата:** 2026-11-04
- **Связано:** [business-model-zavhoz-ru.md](../guides/business-model-zavhoz-ru.md) · ADR 0001 (стек сохраняем) · ADR 0003 (домен объявлений — архив)

## Контекст

Репозиторий развивался как **Объявки BY** (C2C доска объявлений, S0–S7). Владелец продукта направил детальную бизнес-модель B2B-сервиса «Завхоз на аутсорсе» (фасилити / мелкий ремонт для коммерческих точек + сеть мастеров) и явно указал: **переходим на эту модель вместо доски объявлений**.

## Решение

1. **Продуктовый фокус** с этой даты — платформа **Завхоз** (единое окно для бизнеса + диспетчеризация мастеров), не C2C-объявления.
2. **Код/документация Объявки BY** не удаляем сразу: замораживаем как reference / возможный донор паттернов (auth, upload, BY geo, FSM, in-app thread). Новые фичи объявлений (S8–S9) **не делаем**, пока не будет отдельного решения «возобновить».
3. **Стек** (ADR 0001) оставляем: Next.js App Router, FSD, Prisma, Postgres, CSS Modules, Better Auth, Yarn — переиспользуем монолит под новый домен, а не уходим на Tilda/Битрикс как целевую архитектуру (Tilda/CRM допустимы только как временный ops-костыль вне репо, если понадобится до первого кода).
4. **Домен объявлений** (ADR 0003) получает статус **архив / superseded для продукта**. Новый канон сущностей — отдельный ADR 0005 + guide (WorkOrder, Site/Object, Master, BusinessOrg, акт/фото отчёт, прайс) — **до** массового рефакторинга кода.
5. **MVP продукта** (следующий шаг после доменного ADR): заявка с фото → категория/оценка → назначение мастера → фото «после» → статус закрытия. Платежи, ЭДО, подписки сетей, гео-радиус 3–5 км — фаза 2+ (YAGNI).

## Последствия

- Обновить `strategy-plan`, `sprint-map`, `docs/README`, project rules: бренд/цель = Завхоз.
- Changelog: зафиксировать пивот.
- Не ломать работающий VPS `:3010` объявлений без плана миграции URL/данных.
- Крупный rewrite схемы Prisma — только после ADR 0005.
